# 技术路线：消费电子维修智能诊断系统

## 1. 整体技术路线图

```
数据层                    存储层                    推理层                    展示层
─────────              ─────────               ─────────               ─────────
维修    →       Qdrant向量库     →      RAG检索增强    →        Gradio Web UI
数据           (53,000向量)            (语义相似匹配)          (故障诊断)
                       Neo4j图数据库    →      CoT推理链      →        (知识图谱)
                       (50,585关系)            (逐步展示思考)          (向量空间)
CSV→Embedding   →      sentence-transformers   DeepSeek LLM    →      流式输出
                       (all-MiniLM-L6-v2)      (文本推理)             (实时反馈)
                       MiMo-V2.5       →      多模态分析      →      照片上传
                       (视觉模型)              (图片理解)             (图片分析)
```

## 2. 核心技术栈

### 2.1 LLM层

| 组件 | 技术 | 用途 |
|------|------|------|
| 文本推理 | DeepSeek v4-pro | 故障诊断、方案生成 |
| 图片分析 | MiMo-V2.5 | 现场照片分析（base64输入） |
| Embedding | all-MiniLM-L6-v2 (384维) | 文本向量化，本地CUDA加速 |

| 组件 | 技术 | 用途 |

## 3. 关键技术详解

### 3.1 RAG（检索增强生成）

```
用户提问: "手机屏幕碎了怎么修"
         ↓
Embedding: 将查询文本转为384维向量
         ↓
Qdrant检索: 在53,000条向量中找到Top-5语义最相似的记录
         ↓
上下文注入: 将检索到的维修案例作为上下文注入LLM Prompt
         ↓
LLM生成: DeepSeek基于检索结果生成针对性诊断
```

**效果**：纯LLM只依赖训练数据的通用知识；RAG让LLM"查阅"真实维修记录后给出更精准建议。

### 3.2 CoT（思维链推理）

```
Step 1: 🔍 正在检索知识库...         → Qdrant语义搜索
Step 2: 📚 检索到3条相关记录         → 展示检索结果
Step 3: 🧠 LLM正在分析...           → 流式输出分析过程
Step 4: 📋 诊断结果                  → 结构化故障判断
Step 5: 🔧 维修方案                  → 步骤/工具/备件
Step 6: ✅ 诊断完成                  → 生成工单
```

**效果**：用户实时看到AI的"思考"过程，增强可信度和可解释性。

### 3.3 向量数据库（Qdrant）

**原理**：将文本转换为高维向量（Embedding），通过向量距离计算语义相似度，实现"理解语义"的搜索。

```
传统关键词搜索:  "屏幕碎了" ≠ "display broken"  （无法匹配）
向量语义搜索:    "屏幕碎了" ≈ "display broken"   （语义相似，距离近）
```

**工作流程**：
```
离线阶段（数据导入）:
  CSV维修记录 → Embedding模型 → 384维向量 → Qdrant存储

在线阶段（用户查询）:
  用户描述 → Embedding模型 → 384维查询向量
       ↓
  Qdrant余弦相似度搜索 → 返回Top-K最相似的维修记录
       ↓
  将检索结果注入LLM Prompt → 生成针对性诊断
```

**Qdrant配置**：
- 向量维度：384（all-MiniLM-L6-v2）
- 距离度量：余弦相似度（Cosine）
- 存储数据：53,000条维修记录的Embedding向量
- Payload字段：product_category, fault_type, brand, text摘要
- 检索延迟：< 100ms

### 3.4 知识图谱（Neo4j）

```
(华为) --------产品--------> (笔记本) --有_组件--> (屏幕)
  |                            |
  +--产品--> (手机)             +--有_组件--> (背光)
                               |
                               +--有_组件--> (LED)
```

**Neo4j图谱规模**：
- 41 个设备节点（Mobile, Laptop, Printer, Tablet 等）
- 56 个故障类型节点（Screen, Power/battery, Ink cartridge 等）
- 333 个品牌节点（Apple, Samsung, HP, Canon 等）
- 50,585 条维修记录节点
- 57,918 条关系边

### 3.5 多模态分析（MiMo-V2.5）

```
用户上传照片 → PIL转numpy → base64编码 → 多模态LLM大模型
                                              ↓
                                     图片分析结果（设备类型/故障现象/损伤程度）
                                              ↓
                                     拼入诊断Prompt → LLM大模型综合分析
```

## 4. 数据处理流程

```
CSV数据集 (53,007条)
    ↓
清洗: 过滤空字段、统一编码
    ↓
Embedding: sentence-transformers/all-MiniLM-L6-v2 (384维)
    ↓
Qdrant: 存储向量 + payload（产品类别/故障类型/品牌/文本摘要）
    ↓
Neo4j: 构建实体关系图谱（Device/FaultType/Brand/RepairRecord）
```
