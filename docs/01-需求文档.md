# 需求文档：消费电子维修智能诊断系统

## 1. 项目背景

消费电子维修行业（手机、笔记本、打印机、平板等）面临以下痛点：

- **经验依赖强**：维修诊断高度依赖工程师个人经验，新手难以快速上手
- **知识分散**：维修手册、案例、故障码散落在不同文档中，检索困难
- **诊断不透明**：传统AI诊断是"黑盒"输出，用户无法理解推理过程
- **工单不规范**：维修工单格式不统一，缺少结构化的备件/工具/安全信息

## 2. 目标用户

| 用户角色 | 核心需求 |
|---------|---------|
| 维修工人 | 快速诊断故障、获取维修步骤、生成规范工单 |
| 维修工程师 | 检索知识库、查看相似案例、辅助复杂故障分析 |
| 技术管理人员 | 了解维修数据分布、故障类型趋势、品牌质量对比 |

## 3. 功能需求

### 3.1 核心功能：智能故障诊断

```
用户输入（文字 + 可选照片）
    ↓
多模态分析→ 分析现场照片
    ↓
知识检索（RAG）→ 从维修记录中找相似案例
    ↓
LLM诊断（CoT+Agent）→ 综合分析故障原因
    ↓
输出：诊断结果 + 维修方案 + 结构化工单
```

**输入**：
- 故障文字描述（必填）
- 现场照片（可选，由MiMo-V2.5多模态模型分析）

**输出**：
- 故障类型判断（屏幕损坏/电池问题/充电口故障等）
- 可能原因列表
- 损伤等级评估（轻微/中等/严重）
- 维修步骤（带工具和注意事项）
- 备件清单
- 安全警告
- JSON格式维修工单

### 3.2 知识库管理

- 导入维修手册（支持PDF/Word/Excel）
- 添加维修案例
- 添加故障码
- 语义检索知识库

### 3.3 可视化展示

| 页面 | 功能 | 技术 |
|------|------|------|
| 知识图谱 | 展示设备-故障-品牌关系网络 | Neo4j → NetworkX → Matplotlib |
| 向量空间 | 展示Embedding降维后的语义聚类 | Qdrant → t-SNE → Matplotlib |

### 3.4 对比演示页面

| 页面 | 功能 | 端口 |
|------|------|------|
| 纯LLM | 无工具直接调用API | 7870 |
| LLM+RAG | 检索知识库后诊断 | 7871 |
| LLM+RAG+CoT | 检索+流式推理过程 | 7872 |

## 4. 非功能需求

- **响应时间**：文本诊断 < 30秒，图片分析 < 15秒
- **数据规模**：支持 53,000+ 条维修记录的检索
- **可用性**：Web界面无需安装，浏览器直接访问
- **可扩展性**：支持导入更多维修数据、扩展设备类型

## 5. 数据来源

数据来自 [Open Repair Alliance](https://openrepair.org/) 开放维修数据集，包含真实维修记录：

| 数据文件 | 记录数 | 内容 |
|---------|--------|------|
| repairs.csv | 48,676 | 综合维修数据集 |
| mobiles.csv | 1,916 | 手机维修（含故障类型） |
| tablets.csv | 647 | 平板维修（含故障类型） |
| batteries.csv | 995 | 电池维修（含故障障碍） |
| printers.csv | 773 | 打印机维修（含故障类型） |
| **合计** | **53,007** | |

## 6. 技术约束

- Python 3.10+
- DeepSeek API（文本LLM）
- MiMo-V2.5 API（图片分析）
- Qdrant（向量检索）
- Neo4j（知识图谱）
- Gradio（Web UI）
